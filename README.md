# semantic_search_eval — 법령 의미 검색 평가셋 구축 및 텍스트 · KG · 하이브리드 비교

> 졸업논문 **Part 3 · 실무 검증 — 의미 유사 검색**
> 논문 제목의 "의미 관계 **검색**"을 링크 예측 지표만이 아니라 실제 검색 과제로 평가합니다. 국방 법령 KG에서 4가지 검색 과제(163개 질의)를 자동·수작업으로 만들고, 텍스트 임베딩 · KG 임베딩 · 둘을 합친 하이브리드를 비교합니다.

## 1. 평가셋 (`data/eval/semantic_eval.json`)

| 과제 | 질의 → 정답 | 예시 | 질의 수 | 생성 방법 |
|---|---|---|---|---|
| **T1 표기변이** | PDF 추출 오류·가운뎃점 변이 노드 → 대표 노드 | `방위사 업법 시행령` → `방위사업법 시행령` | 86 | 공백·가운뎃점을 지운 키로 자동 군집 |
| **T2 약칭** | KG 밖 텍스트 질의 → 정식 법령/기관 | `국가계약법` → `국가를 당사자로 하는 계약에 관한 법률`, `방사청` → `방위사업청` | 19 | 공식 약칭 · 실무 통칭 · 문서 내 정의어 수작업 |
| **T3 상위법령** | 하위 법령 → 모법 | `군수품조달관리규정` → `방위사업법` 외 5 | 19 | KG 상위법령 관계 |
| **T4 인용관계** | 말뭉치 법령 → 그 조문들이 인용하는 법령들 (다중 정답) | `(방위사업청) 보직관리규정` → `군인사법`, `공무원징계령` … | 39 | 조문 인용을 법령 단위로 집계 |

T1·T2는 **이름(텍스트)** 으로 풀어야 하는 과제이고, T3·T4는 **구조(관계)** 로 풀어야 하는 과제입니다. 검색 후보는 조문을 제외한 모든 엔티티(법령·외부 법령·기관)이고 질의 자신은 제외합니다.

## 2. 비교 방법

| 방법 | 표현 | 비고 |
|---|---|---|
| Text | 엔티티 이름 문자 2~4-gram TF-IDF + LSA (100차원) | 외부 모델 불필요 |
| KG-TransE / KG-Ours | 링크 예측으로 학습한 엔티티 임베딩 (seed 3개 평균) | 구조 정보 |
| Hybrid | `[α·Text ; (1−α)·KG]` 단위벡터 결합. KG 밖 질의(T2)는 텍스트 최근접 엔티티의 KG 벡터를 빌려 씀 | α = 0.3 / 0.5 / 0.7 |

점수는 코사인 유사도, 지표는 MRR(첫 정답 기준) · Hits@10 · Recall@10(T4 다중 정답)입니다.

## 4. 실행 방법

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python scripts/01_build_evalset.py          # 평가셋 (수 초)
python scripts/02_train_embeddings.py       # 임베딩 학습 6런 (약 5분, 저장본이 있으면 건너뜀)
python scripts/03_evaluate.py               # α=0.5
python scripts/03_evaluate.py --alpha 0.3
```

## 5. 결과 (MRR / Hits@10)

| 방법 | T1 표기변이 | T2 약칭 | T3 상위법령 | T4 인용관계 | T4 Recall@10 |
|---|---|---|---|---|---|
| Text | **0.851** / 0.988 | **0.236** / 0.526 | 0.163 / 0.316 | 0.225 / 0.513 | 0.088 |
| KG-TransE | 0.044 / 0.058 | – | 0.299 / 0.614 | 0.348 / 0.769 | 0.142 |
| KG-Ours | 0.042 / 0.070 | – | 0.175 / 0.368 | 0.304 / 0.573 | 0.092 |
| Hybrid(Text+TransE) α=0.5 | 0.525 / 0.783 | 0.136 / 0.368 | 0.318 / 0.491 | 0.360 / 0.692 | 0.141 |
| Hybrid(Text+TransE) α=0.3 | 0.279 / 0.461 | 0.069 / 0.088 | **0.382** / **0.702** | **0.422** / **0.795** | – |
| Hybrid(Text+Ours) α=0.7 | 0.736 / **0.996** | 0.208 / **0.596** | 0.188 / 0.351 | 0.242 / 0.573 | – |

(KG 단독은 KG 밖 질의(T2)를 표현할 수 없어 "–". 전체 표는 `results/semantic_search*.md`)

### 해석

1. **이름으로 푸는 과제(T1·T2)는 텍스트가 압도적**이고, KG 임베딩은 거의 못 풉니다(MRR 0.04). 표기가 갈라진 노드들은 서로 다른 조문에서 인용되어 KG 구조상 가까울 이유가 없기 때문입니다. 이 결과는 데이터 구축 단계의 정규화([law_triple_extraction](https://github.com/Ikuuuu/law_triple_extraction) v1.1)가 왜 필요한지 보여 줍니다.
2. **구조로 푸는 과제(T3·T4)는 KG 임베딩이 텍스트보다 낫고**, 하이브리드(α=0.3)가 가장 좋습니다 (T4 MRR 0.225 → 0.422). 텍스트와 구조는 서로 다른 정보를 담고 있어 결합하면 이득이 납니다.
3. **코사인 검색에서는 Ours가 TransE보다 낮습니다** (T3 0.175 vs 0.299). Ours의 손실은 `(h, r, ?)` 점수 함수의 순위를 개선하도록 설계되어 있고, 특히 `L_type`이 같은 클래스 엔티티를 한곳으로 모읍니다. 그래서 관계를 지정하지 않는 "비슷한 엔티티 찾기"에는 오히려 불리합니다. **링크 예측 성능 향상이 곧 유사도 검색 향상은 아니라는 점**을 논문 한계로 명시하고, 검색 단계에서는 관계를 지정한 질의(`06_inference.py --relation`)를 쓰는 편이 맞습니다.
4. 실무 적용 시에는 **질의 유형에 따라 α를 바꾸는 방식**(이름 질의 α↑, 관계 탐색 α↓)이 바로 적용할 수 있는 개선책입니다.

## 6. 한계

- T2는 19개로 작고 수작업 목록입니다. 공식 약칭은 국가법령정보센터 표기를 따랐습니다.
- T3 정답은 KG의 상위법령 관계 자체라 KG 임베딩이 학습 때 본 정보입니다. 그래서 T3는 "학습한 구조를 유사도 공간에 얼마나 잘 남기는가"를 재는 과제로 해석해야 합니다.
